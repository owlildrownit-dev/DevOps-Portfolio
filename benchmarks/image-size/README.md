# Размер Docker-образа: однослойный vs multi-stage

| Файл | Назначение |
| --- | --- |
| `Dockerfile.single-stage` | Однослойный вариант: компилятор и `libpq-dev` остаются в образе, запуск от root |
| [`../../app/Dockerfile`](../../app/Dockerfile) | Multi-stage вариант, используется при выкладке |
| `measure.sh` | Сборка обоих образов с нуля, размеры из `docker image inspect`, отчет `results/sizes.md` |

```bash
./measure.sh
```

## Результат (GitHub Codespaces, 28.10.2026)

| Прогон | single-stage, байт | multi-stage, байт | Сборка с нуля | Уменьшение |
| --- | --- | --- | --- | --- |
| 1 ([скриншот](../../docs/screenshots/02-docker-sizes.png)) | 738 410 968 (704,2 МБ) | 207 651 171 (198,0 МБ) | 62 с / 55 с | 71,9% |
| 2 ([`results/sizes.md`](results/sizes.md)) | 738 410 763 (704,2 МБ) | 207 651 183 (198,0 МБ) | 60 с / 53 с | 71,9% |

Расчет: (738 410 763 − 207 651 183) / 738 410 763 × 100 ≈ 71,9%.
Проверки: в итоговом образе нет `gcc`, приложение и `psycopg2` импортируются.

![sizes](../../docs/screenshots/02-docker-sizes.png)

## Решения

1. **Multi-stage:** стадия `build` с `build-essential` и `libpq-dev` собирает wheel-файлы,
   итоговая стадия получает только wheel-файлы и runtime-библиотеку `libpq5`.
2. **`RUN --mount=type=bind,from=build`:** wheel-файлы подключаются только на время установки
   и не остаются отдельным слоем (`COPY` + `rm` в следующем слое размер не уменьшил бы).
3. **Порядок слоев:** код копируется последним, правка кода не сбрасывает кэш зависимостей.
4. **Безопасность:** пользователь `app` (uid 10001), `--no-install-recommends`, очистка списков apt в том же слое.
