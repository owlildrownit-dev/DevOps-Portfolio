# infra: Terraform + Ansible

Deploys the service to a Docker host with a single command.

```bash
./deploy.sh                      # version 1.0.0
APP_VERSION=1.1.0 ./deploy.sh    # upgrade, rolling update one replica at a time
./destroy.sh                     # tear the environment down
```

Requirements: Docker, Terraform 1.5+, `ansible-core`, the `docker` Python package and
the `community.docker` collection (`scripts/setup-tools.sh` installs all of them).

## Separation of concerns

| Tool | Responsibility | Location |
| --- | --- | --- |
| Terraform | Network, volume and the PostgreSQL container (waits for its healthcheck); generates variables for Ansible | `terraform/` |
| Ansible | DB migration, BuildKit image build, rolling update, nginx, smoke test | `ansible/` |
| `deploy.sh` | Runs both stages and records their duration in `results/deploy_times.csv` | |

## What is automated

| Step | Manual process | Automated | Where |
| --- | --- | --- | --- |
| Network and storage | `docker network/volume create` | Terraform | `docker_network`, `docker_volume` |
| Database | start it, set the password, wait until it is ready | Terraform, `wait = true` on the healthcheck | `docker_container.db` |
| Deployment parameters | copy names and addresses into configs | a variables file generated by Terraform | `local_file.ansible_vars` |
| Schema migration | run psql by hand | idempotent migration | `roles/db_migrate` |
| Image build | `docker build` on a workstation | build tagged with the release version | `roles/app` |
| Replica upgrade | stop everything, start new containers | one at a time, the next only after the previous one is healthy | `roles/app/tasks/replica.yml` |
| Load balancer | edit nginx.conf | template driven by the replica count, restarted only on change | `roles/lb` |
| Verification | open the site in a browser | liveness, version, readiness and a business endpoint | `roles/smoke_test` |
| Secrets | password kept in notes | environment variable, gitignored file | `deploy.sh` |

## Design decisions

- **State** is stored locally; team use would require a remote backend with locking.
- **The Ansible config** is passed via `ANSIBLE_CONFIG`, because Ansible ignores `ansible.cfg`
  in a world-writable directory (which is the case in Codespaces).
- **Rollback:** `APP_VERSION=<previous> ./deploy.sh`; the image of the previous version remains on the host.
